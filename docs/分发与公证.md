# MacToolbox 分发与 Apple 公证

## 当前状态

0.2.15 已改为拖拽安装的 DMG：`MacToolbox.app`、指向系统 `/Applications` 的 `Applications` 入口及安装说明。App 和 DMG 均使用公司 Developer ID Application 证书签名，包含 arm64 与 x86_64。

**0.2.15 已通过 Apple 公证（Accepted），DMG 票据已装订并验证。** 带下载隔离标记的 DMG 和从中复制出的 App 均通过本机 Gatekeeper，来源为 `Notarized Developer ID`。可分发本次新 DMG，另一台 Mac 的真实下载与首次打开仍需复核。

0.2.14 旧 PKG 的实际检查结果是签名有效、没有装订公证票据，Gatekeeper 返回 `rejected / source=Unnotarized Developer ID`。DMG 是容器，里面放 PKG 或 App 都是合法形式；拖拽安装与安全认可分别处理，改成 App 不会自动消除未公证拦截。

## 安装方式

打开 DMG，将 `MacToolbox.app` 拖到旁边的 `Applications`。更新时先退出旧版并选择替换。随后推出 DMG，从“应用程序”打开 App。首次使用按系统提示允许辅助功能和屏幕采集。

## 在本机配置公证凭据

当前构建机已完成配置，后续版本可沿用 `MacToolbox-notary`。以下步骤供首次配置或凭据失效时使用。Developer 角色可以提交 macOS 公证，无需账户持有人身份，但账户须属于签名所用的公司开发者团队。[Apple 角色权限表](https://developer.apple.com/help/account/access/roles)

1. 使用属于公司开发者团队 `87K7S9485Y` 且有相应权限的 Apple 账户，在 [Apple 账户](https://account.apple.com/)的“登录与安全 → App 专用密码”生成专用密码。[Apple 操作说明](https://support.apple.com/en-us/102654)
2. 在 Finder 双击 [`tools/配置Apple公证.command`](../tools/配置Apple公证.command)。脚本只询问 Apple 账户邮箱，由 Apple 的 `notarytool` 提示安全输入专用密码，验证后存入本机钥匙串，profile 名称为 `MacToolbox-notary`。
3. 凭据配置不上传安装包。配置完成后返回聊天，继续当前候选的公证；密码、验证码与私钥不需要进入聊天或项目文件。

## 构建、提交与验收

构建双架构 App 并生成拖拽 DMG：

```sh
MACTOOLBOX_ARCHITECTURES=universal MACTOOLBOX_BUILD_CONFIGURATION=release \
  MACTOOLBOX_APP_OUTPUT=/private/tmp/MacToolbox-release-$(id -u)/MacToolbox.app \
  sh tools/build_app.sh -Xswiftc -warnings-as-errors
sh tools/package_dmg.sh /private/tmp/MacToolbox-release-$(id -u)/MacToolbox.app
```

经授权后，把指定 DMG 提交给 Apple 公证服务进行安全扫描：

```sh
sh tools/notarize_dmg.sh "$PWD/build/MacToolbox-0.2.15-universal.dmg" MacToolbox-notary
```

脚本只在 Apple 返回 `Accepted` 后装订票据，再验证票据、DMG 签名、Gatekeeper 与映像完整性，最后重新生成 SHA-256。提交结果和拒绝原因保存在 `build/notarization/`。任何一步失败都不会输出公证及分发检查通过。

超时并不代表 Apple 已取消处理；应使用结果中的提交 ID 查询进度，再继续装订及验收，避免误把超时当成通过或盲目重复提交。

公证与本机验收完成后，仍需在另一台正常启用 Gatekeeper 的 Mac 上测试真实下载、拖拽安装和首次打开。首次正常的“从互联网下载，是否打开”确认可能仍然出现。无需通过关闭 Gatekeeper 或删除隔离属性来验收。
